# Contributing

Thank you for improving DigitalPlat Domain OSS.

1. Open an issue for significant behavior or data-model changes.
2. Create a focused branch and keep unrelated changes separate.
3. Add tests for new behavior and security boundaries.
4. Run `.venv/bin/ruff check .` and `.venv/bin/pytest`.
5. Update documentation and migrations when the public API or database changes.

Never include credentials, production data, or private infrastructure details in issues, fixtures, screenshots, or commits. Report security concerns through the private process in [SECURITY.md](SECURITY.md).
